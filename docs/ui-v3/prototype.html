v3「清单工作台」设计要点

核心命题不是「更好看」，而是把屏幕还给列表——这个 App 只做一件事：从上百年软件里挑出要保留的。

一、先算空间账

二、八条交互改动

#改动解决什么
1导出按钮跟随选择出现（底部浮动条）原来「已选 N」和「导出」在右下角，离列表远；现在选择一发生，动作就在视线下方
2整行可点即切换勾选，命中区 48px原来只有 19px 的方块能点，批量勾选要点得很准
3取消勾选 / 清空 / 反选 一律可撤销（5.2s）整行可点的代价是误触（尤其滚动时）；没有回退路径比「点不准」更糟
4视图三态：全部 / 已选 / 未选任务本质是「找出还没勾的」，只给「仅看已选」是反向视图
5全选 / 全不选 / 反选 收进「⋯」与快捷键三个低频按钮常驻工具条，占掉近 200px；Ctrl A 仍在
6计数随搜索联动（faceted search）原来统计卡是全局静态数，搜完不知道还剩多少；现在分段上的数字就是当前范围内的数量
7「无安装源」行不可勾选，并直说后果原来置灰但不说为什么；现在写明会进核对清单，用户不会以为漏选
8导出前先看到 3 个文件清单与影响面；导出后给「打开文件夹」导出是唯一有后果的动作，先给预览再执行；成功后不留在「已完成」死胡同里

三、约束

项规格
窗口默认 1240×880，最小 960×600；1040 / 960 两档降级只压缩不隐藏（搜索框 340→220→180、分组分段收内边距、重新扫描文字收成图标）
行高舒适 48 / 紧凑 42（只换度量令牌，结构不变）
选中态底色 + 左侧 2px 竖条 + 复选 三重信号；主名保持正文色——四重蓝会让长列表更难扫读
命中区所有可点元素 ≥ 32px，列表行 48px，窗口按钮 44×44
撤销取消勾选 / 清空 / 反选 / 全选本组：5.2s 内可撤销；连续操作以最近一次为准
对比度正文 16.9:1、次级 7.0:1、占位 3.1:1（WCAG AA）
键盘Ctrl F 搜索 · Ctrl A 全选可见 · Ctrl Shift A 清空 · Ctrl I 反选 · Ctrl Z 撤销 · Ctrl E 导出 · Space 勾选当前行 · ↑↓ 移动 · Shift 点击 连选 · Esc 逐层关闭
动效120ms 微交互 / 180ms 常规 / 260ms 抽屉；尊重 prefers-reduced-motion
主题浅色 / 深色同键名换值，组件零改动

四、第三轮复查修掉的 7 个缺陷

缺陷实测 / 证据改法
浮动选择条遮住列表末行滚到底时末行被压 57px（超过一整行），最后一行永远点不到选中时给滚动区补 64px 底部留白（.pad-bar）+ scroll-padding-bottom
深色主题实心按钮看不清白字压在 #60a5fa 上只有 2.54:1，远低于 AA 的 4.5实心按钮改用固定的 --brand-solid，实测 5.17:1
「⋯」是假按钮点开只弹一条 toast 念快捷键，等于没有菜单换成真实菜单：勾选视图内全部 / 全不选 / 反选 / 导出配置… / 打开数据目录，支持 Esc 与点外关闭
不勾选就找不到导出导出按钮只存在于浮动条，0 选中时整条隐藏，入口消失菜单里常驻「导出配置…」，0 选中时置灰而非消失
撤销只有鼠标通路toast 5.2s 后消失，键盘用户没有回退方式补 Ctrl Z，与 toast 的「撤销」共用同一份快照
空态里有死按钮没有关键词时「清除搜索」点了没反应按当前条件显示/隐藏两个按钮
动效降级只写在文档里CSS 里 reduced-motion 媒体查询 0 条补上媒体查询；WPF 侧对应 ClientAreaAnimation=false

原型可交互：搜索、分组筛选、视图三态、勾选（含 Shift 连选）、撤销、导出抽屉、日志抽屉、深浅主题、密度与窗口宽度（1240/1040/960）切换均已实现。

## 1. 诊断：为什么必须重做，而不是换个配色

这个工具只做一件事：**从上百年软件里挑出要保留的**。所有设计决策都应服务于「看得见更多行、勾得更快、导得更放心」。现有界面在这三件事上各有一处结构性问题。

### 1.1 空间账（1240×880 默认窗口，实测）

| 区域 | v2 占用 | 内容 |
|---|---|---|
| 标题栏 | 52 | 品牌标 + 标题 + 版本标签 + 窗口按钮 |
| 头部 | 80 | 一行副标题 + 4 张 104×70 统计卡 |
| 工具条 | 74 | 搜索框、重新扫描、仅看已选、全选/全不选/反选 |
| 分组胶囊行 | 36 | 全部 / 软件 / 运行库 / 不支持 |
| 列表卡 | **420** | 唯一的产出区 |
| 日志面板 | 160 | 常驻，即使空闲也占 150px |
| 底栏 | 58 | 状态文字 + 已选计数 + 导出按钮 |
| 固定占用合计 | **460** | 占窗口高度 52% |

结论：**列表只拿到 48% 的高度，可见 9 行**（行高 46）。而 4 张统计卡里的 4 个数字，与分组胶囊行是同一组信息，界面上重复出现了两次。

### 1.2 六个可用性问题

| # | 问题 | 证据 |
|---|---|---|
| 1 | ~~勾选靠 19px 方块，整行不可点~~ **（此条诊断有误，见下方更正）** | ~~`PackageRowControl.xaml` 只有 `CheckBoxEx` 可交互~~。**实测：v2 的 `PackageRowControl` 已经实现了 `MouseLeftButtonUp → RaiseToggle`，整行本来就可点**。真正的问题是行高只有 46、选中态只有一层底色、没有左侧竖条，长列表里「哪些勾了」要靠逐个找复选框 |

## 2. 设计方向

**清单工作台（List-first Workbench）**：一个视图、一条命令条、一个主角。

三条原则：

1. **列表优先**——任何不直接帮助「找 + 勾」的常驻元素都要让位；能按需出现的，绝不常驻。
2. **动作跟着上下文**——有选择才出现导出；有异常才出现排障；日志只在状态条留一行。
3. **同一信息只出现一次**——分组计数合并进筛选器，删掉重复的统计卡。

**明确不做的事**（避免过度设计）：

| 被否方案 | 原因 |
|---|---|
| 左侧导航栏（软件/运行库/日志/设置） | 只有一类对象，导航层级是负收益，还要吃掉 200px 宽度 |
| 主从双栏（列表 + 详情面板） | 详情只有 3 个字段（名称/包 ID/版本），右栏 90% 是空白 |
| 深色为主视觉 | 系统工具在白天办公场景使用，浅色为默认，深色作为并列主题提供 |

## 4. 设计令牌

### 4.1 颜色

品牌色沿用 Azure（`#2563EB`，白底对比度 5.2:1，可同时作文字色），不换主色——v2 选择它的理由（一套色两用、达 AA）依然成立，v3 只做**语义收敛**与**新增状态**。

| 令牌 | 值 | 用途 |
|---|---|---|
| `brand` / `brand-hover` | `#2563EB` / `#1D4ED8` | 选中、焦点、链接、文字型强调 |
| `brand-solid` / `brand-solid-h` | `#2563EB` / `#1D4ED8` | **实心按钮专用**，两套主题都取 600 号色。深色主题里 `brand` 是 `#60A5FA`，白字压上去只有 2.54:1；实心底不能跟随主题变浅 |
| `brand-soft` / `brand-line` | `#EFF6FF` / `#DBEAFE` | 选中底、标签底、hover 描边 |
| `brand-grad` | `135° #2563EB → #0EA5E9` | 仅品牌标使用（按钮一律实色） |
| `surface` | `#FFFFFF` | 标题栏、命令条、状态条、列表卡 |
| `bg` | `#F2F4F9` | 列表卡以外的页面底 |
| `text` / `text-2` / `text-3` / `text-4` | `#12161F` / `#5A6376` / `#7B8496` / `#A6AEC0` | 主名 / 次要 / 辅助 / 占位 |
| `line` / `line-soft` | `#E6E9F1` / `#F2F4F9` | 结构分隔 / 行分隔 |
| `row-hover` / `row-sel` | `#F6F8FD` / `#EFF5FF` | 行 hover / 勾选行底 |
| `bar` | `#1B2130` | 浮动选择条（深色面，见 §5.6） |
| `ok` / `warn` / `err` / `teal` | `#067647` / `#B45309` / `#DC2626` / `#0E7490` | 成功 / 警告与无安装源 / 失败 / msstore |

**分组色**：软件 `#2563EB`、运行库 `#0E7490`、无安装源 `#D97706`，只用于分组头的 6px 色块和分段里的小圆点，不做大面积填充——分组是「属性」不是「品牌」。

**对比度实测**：正文 16.9:1、次要文字 7.0:1、占位 3.1:1、实心主按钮白字 5.17:1（浅色/深色同值），均达 WCAG AA（正文 ≥4.5:1）。深色主题下若让实心按钮跟随 `brand`（`#60A5FA`），白字仅 2.54:1——这是 v3.1 的一个真实缺陷，v3.2 用 `brand-solid` 修掉。

### 4.2 字号（WPF 设备无关像素，0.5 的倍数）

| 层级 | 值 / 行高 | 用途 |
|---|---|---|
| 窗口标题 | 13.5 / 18 | 标题栏 |
| 对话框标题 | 16 / 22 | 导出抽屉 |
| 行主名 | 13.5 / 18，500 | 列表行 |
| 正文 | 12.5 / 18 | 工具条、按钮 |
| 辅助 | 11.5 / 16 | 状态条、分组头、说明文字 |
| 微型 | 11 / 15 | 包 ID、时间戳、标签 |
| 数字 | 22 / 26，600 | 空态与抽屉中的统计 |

比 v2 整体小半级（v2 标题 24、行 13.5）：标题栏从 52 收到 44 后，24px 的标题会把 44px 撑满；同时 13.5 的行主名在 48px 行里更稳。

### 4.3 圆角 / 阴影 / 动效

- 圆角阶：`4`（标签）/ `6`（输入、小按钮）/ `8`（按钮、行）/ `12`（卡片）/ `16`（窗口、抽屉）
- 阴影三级：`1px 2px`（贴地）、`4px 12px -2px`（浮起）、`18px 44px -12px`（抽屉/选择条）
- 动效：`120ms` 微交互、`180ms` 常规、`260ms` 抽屉滑入；缓动 `cubic-bezier(.2,0,0,1)`；尊重系统「减少动态效果」

## 5. 组件规格

### 5.1 标题栏（44）

品牌标 22×22、圆角 7、渐变底 + 12px 白色下载箭头；应用名 13.5/600；1px 分隔；扫描状态胶囊（6px 圆点 + 11.5 文字）：

| 状态 | 圆点 | 文案 |
|---|---|---|
| 就绪 | 绿色静止 | 已扫描 · 39 个软件 · 12 秒前 |
| 扫描中 | 蓝色呼吸（1.6s） | 正在扫描 · 已读 12 / 39 |
| 异常 | 红色 | winget 不可用 |

窗口按钮 44×44（原 44 宽 × 52 高，与标题栏收窄同步），关闭按钮 hover 变 `#E5484D`。

**为什么把副标题挪走**：副标题是「勾选要保留的软件，导出后可一键重装」这类说明，属于首次使用才需要的信息，现在只在空态出现，不再常驻。

### 5.2 命令条（56）

从左到右：搜索框（弹性，340 上限，最小 180）→ 分组分段器 → 弹性空隙 → 视图三态（全部/已选/未选）→ 重新扫描 → ⋯

- **搜索框**：33 高、圆角 8、`bg=#F2F4F9` 无描边；聚焦时变白底 + 1px 品牌描边 + 3px 外发光；右侧 `Ctrl F` 键位提示在聚焦时淡出（不占位）
- **分组分段器**：轨道 `#EEF1F7` + 3px 内边距，选中项白底 + 1px 阴影。**计数随搜索实时变化**（faceted search）——搜「code」时显示「全部 1 / 软件 1 / 运行库 0 / 不支持 0」，用户立刻知道这个关键词在每个分组里的分布
- **视图三态（全部 / 已选 / 未选）**：三个轻量文字按钮，选中项品牌浅底。**为什么不做成开关**——用户真正要做的是「找出还没勾的」，只给「仅看已选」等于只提供反向视图；三态一次到位，且视觉权重刻意低于左侧分组筛选（分组是主筛选，视图是次筛选）
- **重新扫描**：描边按钮，扫描中变为禁用 + 文字「取消扫描」
- **⋯ 是真菜单，不是提示**：勾选当前视图全部 / 全不选 / 反选 / 导出配置… / 打开数据目录；`Esc` 关闭并回焦到按钮，点外关闭。菜单第一项自动获焦，`↑↓` 可在项间移动
- **导出入口不依赖勾选**：浮动条在没有选择时不存在，所以「导出配置…」必须在菜单里常驻，0 选中时置灰而不是消失——否则用户想导出时找不到入口

### 5.3 列表行（48）

```
[19 复选 12] [主名 13.5/500 + 包 ID 11/11 mono] ……… [来源标签 10] [版本 88 右对齐 11 mono]
```

- **整行可点**：点击任意位置切换勾选，复选只是状态显示器。这是本次最重要的一处改动——批量勾选从「点准 19px」变成「点中这一行」
- **勾选态**：底色 `#EFF5FF` + 左侧 2px 品牌竖条 + 复选填充。**三重信号，主名保持正文色**——早先版本把主名也染成深蓝，等于四重强调，长列表反而更难扫读（蓝色文字会与底色互相削弱）
- **hover**：`#F6F8FD`，复选描边转为 `brand-400`（预告「这里可点」）
- **不可勾选行**（无安装源）：虚线复选、主名降为 `text-3`、标签写「无安装源」，tooltip「没有 winget 安装源，导出时写入核对清单」。**不再只是置灰**——置灰不说原因，用户会以为漏选或被禁用
- **包 ID 缺失**时显示「由第三方安装包安装，未登记包 ID」，比空着更诚实
- 搜索命中用 `#FFFAEB` 底 + 琥珀字高亮，名称与包 ID 同时高亮
- **主名 / 包 ID / 版本三者都带 `ToolTip`**：960 宽下主名截断是常态，截断而不给全称等于信息丢失（WPF 侧用 `TextTrimming=CharacterEllipsis` + `ToolTip={Binding Name}`）

### 5.4 分组头（36，吸顶）

色块 6×6（圆角 2）+ 分组名 11.5/600 + 计数 10.5 mono（已选/总数）+ 右侧**一个**按钮「全选本组 ⇄ 全不选」常驻半透明、hover 与键盘聚焦时实显。吸顶头沿用现有 `StickyGroupHeader` 机制，只是高度从 42 降到 36。

### 5.5 空态 / 加载 / 异常

| 状态 | 表现 |
|---|---|
| 首次扫描 | 骨架屏：6 行占位，缩进与真实行完全一致（复选 19 + 名称两行），顶部 2px 渐变进度条。**不用 spinner 转圈**——骨架屏让人预期「马上就有内容」，转圈只让人等 |
| 搜索无结果 | 图标 + 「没有匹配的软件」+ 具体到「没有名字或包 ID 包含「xxx」的软件」+ 清除搜索 / 重置筛选 |
| 仅看已选为空 | 「还没有勾选任何软件」+「切回『全部』视图，挑几行要保留的再回来」 |
| 仅看未选为空 | 「全部都勾上了」+「没有漏掉的软件了。可以直接导出，或者切回『全部』再看看」 |
| winget 异常 | 琥珀面板 + 三步排查（关掉其它 winget 任务 / 指定 `WPM_WINGET_EXE` / 查看安装引导）+ 重新探测 / 查看安装引导。**给出可执行的下一步，而不是只报错** |

### 5.6 浮动选择条（46，新增）

选择数 > 0 时从底部滑入，居中悬浮在列表卡上方 26px 处：

```
[ 6  项将被导出 · 视图内 1 ] │ 反选  清空 │ [⇩ 导出配置]
```

- **为什么深色**：深色面在浅色界面上是明确的「浮层」信号，且不会与品牌蓝主按钮抢注意力；Gmail / Linear / Notion 都采用同一模式，学习成本为零
- **为什么跟着选择出现**：导出的前提是「选了东西」，动作与前提同处一屏；未选择时它不存在，列表下方不会有死按钮
- **筛选时补充「视图内 N」**：搜索后已选 6、视图内只剩 1，必须说明，否则用户会怀疑漏选
- 反选 / 清空为次级文字按钮，只有「导出配置」是实心按钮——一个浮层里只允许一个主行动
- **必须给滚动区留底部空间**：浮层浮在列表之上，选中时列表末行会被压住（实测 1240×880 下遮 57px，超过一整行），滚到底永远点不到最后一行。规范是：选择条可见时滚动容器补 64px 底部内边距 + `scroll-padding-bottom:64px`（WPF：`ScrollViewer` 内部的 `ItemsPresenter` 加 `Margin="0,0,0,64"`，或 `ListView.Padding`）

### 5.7 状态条（32）

左：最后一条日志（5px 语义色点 + 单行截断），点击展开日志抽屉；紧跟一枚**警告/错误徽章**（`1 个警告`，琥珀底），点击直达日志。

> 徽章是补的一处漏洞：日志收进抽屉后，警告会被后续 INFO 淹没，用户根本不知道要不要点「日志」。有警告就必须在收起状态下可见。

中：弹性空隙。
右：数据目录（tooltip 说明）、winget 版本、日志按钮。

一行顶掉原来的 58px 底栏 + 150px 日志面板：**空闲时零成本，需要时一点即开**。

### 5.8 日志抽屉（覆盖层，236）

从底部滑入，覆盖列表下缘而非挤压它（列表滚动位置与焦点都不动）。头部：标题 + 全部/警告/错误 分段 + 保存 + 收起；正文等宽 11px，时间戳灰、级别着色（INFO 蓝 / OK 绿 / WARN 琥珀 / ERR 红）。

### 5.9 导出抽屉（右侧 Sheet，432）

导出是唯一有后果的动作，所以给它一个「确认页」而不是弹窗：

1. **保存到**：路径前缀 + 文件名输入（`D:\` + `apps.json`）+ 浏览按钮；提示「同名文件已存在时会先问你」
2. **将生成**：3 个文件逐条列出，标注格式差异（`apps.json` UTF-8 无 BOM / `恢复-apps.bat` GBK + CRLF / 核对清单 UTF-8 带 BOM）——这是本产品最容易踩的坑，直接在确认页讲清楚
3. **影响面**：写入 N 个包 / 2 个来源 / M 个软件无法自动装
4. **两条说明**：无安装源项会进核对清单；清单故意不写版本号（及原因）
5. 底部：取消 / 立即导出
6. **导出成功后不是终点**：Toast 里带「打开文件夹」动作，5.2 秒内可点。否则用户导出完就停在「已完成」的死胡同里，还得自己回想存哪了

### 5.10 撤销（新增）

整行可点的代价是误触——尤其滚动时手指压住行再拖动。所以凡是「减少勾选」的操作都必须可回退：

| 触发 | 提示 | 时长 |
|---|---|---|
| 取消勾选某行 | 已取消勾选「Visual Studio Code」+ 撤销 | 5.2s |
| 清空全部（选择条 / `Ctrl Shift A`） | 已清空 11 项勾选 + 撤销 | 5.2s |
| 反选（选择条 / `Ctrl I`） | 已反选视图内 34 项 + 撤销 | 5.2s |
| 全选本组 / 全不选 | 已勾选（或取消）本组 22 项 + 撤销 | 5.2s |

实现用一个快照：操作前深拷贝勾选表，撤销即整体还原。连续操作以最近一次为准（不堆栈，避免「撤销了好几层却不知道回到哪」）。**增加勾选不给撤销**——加错了再点一下就行，噪声大于收益。

## 6. 交互与状态

### 6.1 选择模型

| 操作 | 行为 |
|---|---|
| 点击行任意处 | 切换该行勾选 |
| `Shift` + 点击 | 从上次点击行连选到当前行（只选可勾选行） |
| `Ctrl A` | 勾选**当前视图内**全部可勾选行（不是全局——避免「搜完按全选，结果全选了」） |
| `Ctrl Shift A` | 清空全部勾选（带撤销） |
| `Ctrl I` | 反选当前视图内可勾选行（带撤销） |
| `Space` | 切换焦点行 |
| `↑ ↓` | 行间移动焦点（`tabindex` 单点管理，Tab 不进列表） |
| 分组头按钮 | 未勾满时＝勾选当前视图内该组全部；已勾满时＝整组取消（均带撤销） |
| 反选（选择条） | 仅对当前视图内可勾选行取反 |

**视图与选择是两件事**：视图（全部/已选/未选）只改变可见范围，**从不修改勾选集合**。所以切到「未选」视图后，那个「6 项将被导出 · 视图内 0」的提示是必要的——它说明选择还在，只是没在当前视图里。

勾选 300ms 防抖落盘（沿用现有 `DebounceSaveMs`）；筛选变化不改变勾选集合，只改变可见范围——这是「选择是持久的，视图是临时的」原则。

**误触防线**：整行可点必须配合两条——
1. 按下与抬起之间位移 > 4px 视为拖拽/滚动，不触发勾选（WPF 里在 `MouseLeftButtonUp` 前比对起点坐标）
2. 任何「减少勾选」的操作都弹撤销条（§5.10）

### 6.2 键盘与焦点

`Ctrl F` 搜索 · `Ctrl A` 全选可见 · `Ctrl Shift A` 清空 · `Ctrl I` 反选 · `Ctrl Z` 撤销上一次减少勾选 · `Ctrl E` 导出 · `F5` 重新扫描 · `Esc` 逐层关闭（⋯ 菜单 → 设计说明 → 导出抽屉 → 日志抽屉 → 清空搜索）· `Tab` 在「搜索 → 分段 → 视图 → 动作 → 列表 → 状态条」之间顺序移动。

**撤销必须有键盘通路**：toast 只活 5.2 秒，且不在 Tab 序列的可预期位置，只用鼠标点「撤销」等于对键盘用户没有撤销。`Ctrl Z` 与 toast 按钮共用同一份快照（`undoState`），最近一次操作优先。

焦点环统一 2px `#93B4FB` + 2px 偏移，仅 `:focus-visible` 触发（鼠标点击不出现）。

### 6.3 状态机

`就绪 ⇄ 扫描中 → 就绪 | 异常`；`异常 → 重新探测 → 扫描中`。任意状态下打开抽屉不改变扫描状态；扫描中导出按钮禁用（保证清单与界面一致）。

**WPF 实现注意项**：

1. `backdrop-filter` 不可用。分组头与抽屉的「半透明 + 模糊」在 WPF 里只能用 `BlurEffect`（对 VisualBrush 采样，代价高，长列表滚动会掉帧）。结论：**用 93% 不透明实色代替模糊**，层次交给描边与阴影——与 v2「假玻璃越透越显脏」的判断一致。
2. 浮动选择条的高斯阴影用 `DropShadowEffect BlurRadius=24, ShadowDepth=6, Opacity=0.28`；不要在滚动容器内部挂 Effect，挂在独立覆盖层上。
3. 吸顶分组头已有实现（`StickyHeader` 覆盖层），高度改 36 后要同步 `StickyBarHeight`，否则吸顶位置差 6px。
4. 行内「整行可点」需要处理 `CheckBoxEx` 的点击冒泡：复选设为 `IsHitTestVisible=False` 后，键盘 `Space` 由行控件处理，避免双触发。
5. 分段器的选中态用 `ToggleButton` + `RadioButton` 分组语义，不要用 `ListBox`（会引入选中滚动定位）。

## 14. 修订 v3.3（2026-11-15）：分组头两个链接合并 + 折叠去掉卡顿

### 14.1 「全选本组 / 全不选」合成一个按钮

原来分组头右侧是两个并排的链接，职责重叠：一个说"全勾上"，一个说"全取消"。
改成**一个按钮，文字描述下一步动作**：

| 本组状态 | 按钮文字 | 点击结果 |
|---|---|---|
| 未勾满（0 个或部分） | 全选本组 | 把本组全部可勾选行勾上 |
| 已勾满 | 全不选 | 整组取消 |

三点理由：

1. **状态由计数胶囊回答，按钮只回答"下一步做什么"**。胶囊本来就写着「6/28」，不需要按钮再复述一遍"你已经勾了 6 个"。
2. **不引入第三态**。按钮只有"全勾"和"全清"两个方向，由"是否勾满"二值推导，没有"部分勾选时该点哪个"的歧义——部分状态下按钮仍是"全选本组"，补满是最可能的意图，再点一次即整体取消。
3. **两次点同一个位置可来回**。按钮 `MinWidth=76` 固定，文字在 4 字 / 3 字间切换时不改变宽度——否则"点一次全选、再点同一点取消"会因为按钮变窄而打空。

顺带把原来 12px 纯文字链接换成 24 高、带 hover 底色的文字按钮：原点击区只有文字高约 16px，低于 32px 的最小命中区约定。
「减少勾选」方向（整组取消）现在也会留撤销快照，与逐行取消、清空、反选的规则一致。

> 「winget 不支持」组整组不可勾选，按钮保持隐藏（点击只会得到 0 项，属误导）。

### 14.2 折叠/展开的延迟：不是动画慢，是整表重建

**症状**：点任意分组头，从按下到画面变化能明显感到一段空档。

**根因**：`ToggleGroup` 里调了 `RequestRelayout()`，于是每次折叠都会走一遍完整重建——
`SectionsHost.Children.Clear()` → 重新 `new` 三个 `GroupSectionControl` → 重新 `new` 95 个 `PackageRowControl`
→ 逐个 `Bind` + 高亮分词 → `DispatcherPriority.Background` 里排队执行。折叠本身只需要把行容器
`Visibility` 从 `Visible` 改成 `Collapsed`，控件一个都不用动。

**实测**（应用内 `Stopwatch`，95 个已安装项 / 3 个分组，强制 `UpdateLayout()` 后才停表）：

| 路径 | 单次耗时 |
|---|---|
| 整表重建（旧） | **267 / 280 / 282 ms** ×3 次 |
| 就地折叠（新） | **3.6 – 4.5 ms** ×6 次 |

约 **65 倍**差距。旧路径的 267ms 正是"点下去要等半拍"的来源；新路径已在肉眼不可辨范围。
同一份数据在筛选后的 35 行子集上量到 95ms，说明耗时与行数线性相关，95 行时必然更差。

**改法**：
- `MainViewModel.ToggleGroup` 只改 `_collapsed` 并返回新的展开状态，**不再请求重排**（注释里写清了原因，防止后人"顺手加回去"）。
- 新增 `MainWindow.ToggleGroupInPlace(title, section)`：翻转折叠三角 + `GroupSectionControl.SetExpanded`，
  然后标记吸顶头位置表为脏，并在 `DispatcherPriority.Loaded` 里（等这一帧布局跑完、坐标已更新）重算吸顶头。
- `GroupHeaderControl` 拆出 `SetExpandedVisual(bool)`，供就地翻转时单独调用，不必整头重绑。

**顺带修掉的一个隐患**：`_normalBackground`（hover 结束后要还原的渐变底）原来在 `Bind` 里缓存。
如果鼠标正停在分组头上时发生刷新，缓存下来的会是 hover 底色，"移开鼠标也擦不掉"。现在改为构造时缓存一次。

## 16. 修订 v3.4（2026-11-15）：搜索框输入起点修正

### 16.1 问题

用户看到的现象：点进搜索框，光标和第一个字符出现在离左边框很远的地方，中间空出一大段。
实测不是"看起来远"，是真的远了一倍。

用 `tools/measure-search.py` 在 125% DPI 的实机截图上按列扫描，得到：

| 元素 | 物理 px（相对窗口） | 相对框左 | DIP |
|---|---|---|---|
| 搜索框左边框 | 20 | 0 | 0 |
| 放大镜图标 | 36–52 | 16–32 | 12.8–25.6 |
| 输入文字 `abc` 首像素 | **108** | **88** | **70.4** |
| 设计值 | — | 42.5 | 34 |

设计是 `Padding="34,0,10,0"`，实测 70.4 ≈ 34 × 2 + 边框 1 + 字符左侧留白。**内边距被叠加了两次。**

### 16.2 根因

```xaml
<!-- 错的写法 -->
<Setter Property="Padding" Value="34,0,10,0" />
...
<ScrollViewer x:Name="PART_ContentHost" Margin="{TemplateBinding Padding}" />
```

WPF 的 `TextBox` 会**自己**把 `Padding` 消费一次（`TextBoxView` 的排版原点已经含 padding），
模板里再把 `Padding` 绑到 `PART_ContentHost.Margin` 就是第二份。默认 Aero 模板之所以
把 `Padding` 放在 `Border` 上而不是 `Margin` 上，正是为了避开这一点。

### 16.3 改法

```xaml
<!-- 对的写法：Padding 钉死为 0，缩进只由 Border.Padding 提供一份 -->
<Setter Property="Padding" Value="0" />
...
<Border x:Name="Bd" Padding="34,0,10,0" ...>
    <ScrollViewer x:Name="PART_ContentHost" ... />
</Border>
```

同时把 `SearchPlaceholder` 的 `Margin` 从 `32` 调到 `35`（= 边框 1 + 内缩 34），
让占位文字和真实输入文字**共用同一条起始线**——否则一输入字符，文字会横向跳 3 DIP。

### 16.4 验证

同一脚本二次测量：文字首像素 74 px，框左 29 px → **相对 45 px = 36.0 DIP**（34 + 边框 + 字距），
正好落在图标右边缘（29 DIP）之后 7 DIP。缩进从 70.4 降到 36，**减掉 34.4 DIP**，与"去掉一份 34"完全吻合。

- 对比图：`shots/search-inset-before-after.png`（洋红线标文字起点、蓝线标框左边框）
- 1240 空态 / 输入态、960 窄宽三档均复核（`shots/search-empty-1240.png`、`search-typed-1240.png`、`search-narrow-960.png`）
- 960 下占位文字正常截断为「搜索名称或包…」，图标间距不变
- `267/267` 自测通过、`check_csproj.py` PASS、构建 0 error

### 16.5 这类坑的通用检查

写自定义 `PART_ContentHost` 模板时，`Padding` 只能有一个出口。记两条：

1. `ScrollViewer.Margin` **不要**绑 `TemplateBinding Padding`；
2. 如果确实需要 `TextBox.Padding` 参与布局，就在模板里用它，不要另加 `Margin`。

同类风险点只有这一处（`grep PART_ContentHost` 全仓仅 `TextBox.Search` 一个自定义模板），已确认无第二例。

## 17. 修订 v3.6（2026-11-15）：分段器描边一致性 + 便携数据目录

### 17.1 分段器：为什么"边框有时候不显示"

用户看到的两个现象其实同源：**选中态把「我选中了」这件事，全部压在一根 1px 描边上。**

量一下这三层的颜色，问题就清楚了：

| 层 | 旧值 | 与新轨道的明度差 |
|---|---|---|
| 轨道 `SegTrack` | `#EEF1F7` | — |
| 选中底 `SegOn` | `#EFF6FF`（浅蓝） | ~17 |
| 选中描边 `Brush.Line` | `#E4E8F0` | ~10 |

三层全挤在 10–20 的明度差里，125% DPI 下 1px 描边被抗锯齿摊到 2 个物理像素，
每个像素只剩 40–60% 不透明度——**某些边就"看不见"了，而且断得没有规律**，看起来像没对齐。

雪上加霜的是焦点环：

```xaml
<Trigger Property="IsKeyboardFocused" Value="True">
    <Setter TargetName="Bd" Property="BorderBrush" Value="{StaticResource Brush.FocusRing}" />
</Trigger>
```

`IsKeyboardFocused` 在**鼠标点击后同样为真**。于是点一下「软件」，
它的灰描边当场被刷成蓝框，而旁边同样处于「已选中」的按钮没有这个待遇——
同一排两个胶囊两种样子。再加上 WPF 自带的 `FocusVisualStyle` 虚线框叠在上面，
就成了截图里那个"半截蓝框 + 虚线"的怪东西。

### 17.2 改法

**拉开层次**（`Tokens.xaml`）：

| 令牌 | 旧 | 新 | 说明 |
|---|---|---|---|
| `Brush.SegTrack` | `#EEF1F7` | `#E7EBF3` | 轨道压深一档 |
| `Brush.SegOn` | `#EFF6FF` | `#FFFFFF` | 选中底改纯白，与卡片同色但靠描边区分 |
| `Brush.SegOnLine` | 无 | `#CBD5E4` | 新增，描边单独加深 |

改后对比：轨道→选中底 22，选中底→描边 24，描边→轨道 34（原来 10）。

**焦点环还给键盘**（`Styles.xaml`）：删掉 `IsKeyboardFocused` 的描边 trigger，
改用 `FocusVisualStyle`：

```xaml
<Setter Property="FocusVisualStyle" Value="{StaticResource FocusRing.Inset}" />
```

`FocusVisualStyle` 是 WPF 里唯一「只在键盘导航时出现」的焦点机制——
鼠标点击不显示，Tab / 方向键进入才显示。语义正好对上：鼠标用户看到干净的白胶囊，
键盘用户仍能看到 1.5px 蓝色圆角框（内缩 1px，不覆盖选中态自己的描边）。

### 17.3 便携：数据跟着 exe 走

原来 `AppPaths` 已经支持便携布局（exe 同级 `Data\`），但**默认关闭**，
要用户手动放 `WingetManager.portable` 空文件——一个单文件 exe 的默认行为
却是往用户目录写东西，这本身就不对。

改成三级判定：

1. `WPM_PORTABLE` 环境变量：显式开关，`0/false/no` 强制关闭
2. exe 同目录的 `WingetManager.portable` 标记文件：强制开启
3. **默认：exe 目录下能建 `Data\` 并写入 → 便携**；写不进去（装在 Program Files、
   只读介质、受限目录）才回落 `%LOCALAPPDATA%\WingetManager`

探测复用「建目录 → 写探针文件 → 删探针」三步法，和 `DataDirWritable` 同一份实现
（新增私有 `CanWriteTo`，原方法改为调用它）。

**旧数据不丢**：`MigrateLegacyDataIfNeeded()` 在 `AppConfig.Load()` 之前跑，
满足「便携模式 + 便携目录还没有数据 + 用户目录有数据」三条时，
把 `selection.json` / `settings.json` / `metadata-cache.json` **复制**过来
（不是移动——用户设 `WPM_PORTABLE=0` 回退时数据仍在原处）。日志不搬。
实测首次启动日志：

```
[INFO] 便携模式：数据目录位于 exe 同目录下的 Data 文件夹。
[INFO] 已从旧数据目录 C:/Users/Administrator/AppData/Local/WingetManager 复制 3 个文件到便携目录（源文件保留）。
```

**关于对话框**同步两处：
- 追加一行 `AboutPortableHint`（"当前为便携模式：配置、勾选记录与日志都在 exe 同目录的 Data 文件夹里…"）
- 路径行改成相对形式（`Data\selection.json` / `Data\logs\app.log`）。
  绝对路径前缀太长，`TextTrimming` 会把文件名本身截掉，反而看不出是哪个文件；
  完整路径放进 `ToolTip` 备查。

### 17.4 验证

- 分段器：真实鼠标点击「软件 41」后，白胶囊描边完整、无蓝框无虚线（`shots/p2-crop.png`）；
  分类组与视图组两处并排一致（`shots/p7-bars.png`）

### 17.5 遗留

`WPM_PORTABLE` 之外，用户若想「临时用回用户目录」，目前只能设环境变量。

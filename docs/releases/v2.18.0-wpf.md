# Winget 软件管家 2.18.0（C# WPF 版）— 单文件便携，零依赖

清点本机已安装软件，把可自动重装的包导出为 [winget 官方清单格式](https://aka.ms/winget-packages.schema.2.0.json)。重装系统后把导出的三个文件拷到新机器，双击恢复脚本即可批量装回。

**定位是只导出、不导入**：本工具不会替你安装任何软件，安装动作只发生在恢复脚本由你亲手双击时。

这是 `master` 上 Python/PySide 原版的 **C# + WPF 复刻**（分支 `wpf-rewrite`），UI 与功能逐项对齐 2.18.0；另一条 `winui3-rewrite` 线是 WinUI 3 实现，两条重写线互不干扰。

## 功能

- **扫描** `winget list`，按「软件 / 系统组件·运行库」分节展示，支持搜索、分组折叠、批量勾选
- **导出三种格式**（一套三个文件）：
  - `apps.json` —— UTF-8 无 BOM，可直接喂给 `winget import`
  - `恢复-*.bat` —— GBK + CRLF，双击即按清单批量重装（cmd.exe 对编码敏感，这里踩过坑）
  - `无法自动重装清单-*.html` —— 单文件内联 CSS/JS，离线可开，列出 winget 装不回来的东西及手动处理建议
- **元数据异步核查**：本地缓存 TTL 默认 90 天，可用 `WPM_META_TTL_DAYS` 调整（`0` = 永不过期）
- **便携模式默认开启**：数据在 exe 同级 `Data\`（勾选状态 / 缓存 / 日志），目录不可写时自动回退 `%LOCALAPPDATA%\WingetManager`

## 本轮审计修复

这一版包含一轮全量审计（代码质量 / 功能完整性 / 安全 / 性能 / 配置）的修复，详见 `docs/QA-REPORT.md` §10。

**P0 — 数据丢失**

- `build-release.bat` 每次重建都执行 `rd /s /q dist`，而便携模式的用户数据就在 `dist\Data`。**一次重新构建就会静默清空全部勾选状态**。已改为只删构建产物。

**P1**

- `OpenDataDir` 把未加引号的路径当作整条命令行传给 `explorer.exe`，`Program Files`、含空格用户名下会打开错误位置。
- `JsonReader` 无嵌套深度上限，畸形 JSON 触发 `StackOverflowException` —— .NET 里**不可捕获**，进程直接消失且不留日志。现限制 64 层。
- `MetadataProbe.EnrichAsync` 返回的 `Task` 被丢弃，后台核查失败时界面毫无提示。
- 跨轮次扫描共用字段上的 `CancellationTokenSource`，上一轮迟到的回调会 `Dispose` 掉新一轮的令牌，那一轮从此无法取消。

**P2**

- UTF-8 代码页下 `Encoding.Default` 产出 `U+FFFD` 而不抛异常，旧逻辑拿着乱码提前返回，跳过了 GBK 兜底（界面显示「口口口」）。
- **ANSI 为单字节代码页时（英文/西文 Windows，cp1252）GBK 中文被解成拉丁乱码**（`名称` → `Ãû³Æ`）。单字节页对任何字节都有映射、永远不产出 `U+FFFD`，所以上一道守卫拦不住。现改为：ANSI 是单字节页或 65001 时，严格 GBK 解码先于 ANSI。**这条是本地中文 Windows 永远测不出来、由 CI 在 `windows-latest` 上抓到的。**
- 三处 `FormattedText` 六参过时重载，隐含 `pixelsPerDip = 1.0`，125%/150% 缩放下文字被裁切。修复后编译 **0 warning**。
- `tests/` 下两份分叉的构建脚本合并为转发中间层；`qa_verify.py` 入库并去掉开发机硬编码路径；`.gitignore` 补齐备份/临时目录；`AppPaths.IsPortable` 注释与代码相反。

## 已知局限

- 纯视觉项（对话框首帧高度、无边框窗口最大化留边、字体回退观感）无法自动化，建议肉眼看一眼。
- 便携模式的数据在 `dist\Data`；若把 exe 单独拷到只读目录（如 `C:\Program Files`），数据会自动落到 `%LOCALAPPDATA%`。
- 逻辑层未做 fuzz；`winget list` 的输出格式若大改，解析器需跟着调整（已有 `ParseByGaps` 兜底与 432 条断言护着）。

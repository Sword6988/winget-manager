## 0. 状态机总纲（一切禁用矩阵的基准）

应用只有一个状态变量维度（现有 `self._scanning` / `self.importing`，建议合并为显式状态字段 `self.state`）：

```
BOOT ──自动扫描──▶ SCANNING ──成功──▶ READY ◀──搜索/勾选（READY 内子态）──┐
  │                    │失败                                              │
  │                    └──▶ SCAN_FAILED（页内重试）──[重试]──▶ SCANNING    │
  ▼                                                                       │
SCANNING ◀────────────────[重新扫描]──────────────────────────────────────┤
                                                                          │
READY ──[导入恢复]选文件+确认──▶ IMPORTING ──[取消导入]──▶ CANCELING ──┐   │
                                       │                               │   │
                                       └──结束(成功/失败/取消)──────────┴───┤
                                              │自动重扫描                    │
                                              ▼                            │
                                          SCANNING ────────────────────────┘
```

规则：

| 规则 | 说明 |
|---|---|
| R1 | `SCANNING` 与 `IMPORTING` 互斥。导入结束自动重扫描是唯一自动迁移。 |
| R2 | `CANCELING` 是 `IMPORTING` 的子态：已向 winget 发出终止信号但进程未退出。取消按钮置灰，状态栏显示「正在取消导入…」。winget 退出后回到结束分支。 |
| R3 | `SCAN_FAILED` 不弹窗（视觉规范已定），列表保留旧数据+页内横幅文案，状态栏出现可点「重试」（或复用重新扫描按钮）。 |
| R4 | 任何状态下窗口右上角 ✕ 均可点；`IMPORTING` 时触发关闭确认（见 §3.4）。 |

### 2.1 控件行为精确定义

### 2.3 键盘快捷键表

| 键 | 上下文 | 行为 |
|---|---|---|
| Tab / Shift+Tab | 全局 | 按下方焦点顺序移动 |
| Space | Treeview 有焦点行 | 切换该行勾选（叶子行）；分组行=整组三态切换 |
| Enter | Treeview 有焦点行 | 叶子行=复制包 ID；分组行=折叠/展开 |
| ↑ / ↓ | Treeview 有焦点 | 移动选中行（browse 自带），越过分组头时同样落焦点 |
| ← / → | 焦点在分组行 | 折叠 / 展开 |
| Ctrl+A | 焦点不在搜索框/日志 | 全选（等价「全选」按钮，作用于全量 packages） |
| Ctrl+F | 全局 | 焦点跳到搜索框并全选文本 |
| Esc | 焦点在搜索框 | 清空搜索，焦点移到 Treeview |
| Esc | 焦点在 Treeview | 清除搜索（若激活）；否则无操作 |
| Ctrl+C | Treeview 有选中行 | 复制包 ID |
| Esc | 自绘对话框打开 | 关闭对话框（等同取消），与系统模态习惯一致 |

实现要点：`bind_all` 处理 Ctrl+F；Treeview 键绑定挂 `<space>` `<Return>` `<Control-c>` 等，注意 `return "break"` 阻止默认空格滚动。

### 2.4 焦点顺序（Tab 链）

```
搜索框 → 重新扫描 → 全选 → 全不选 → 反选 → 取消运行库
→ 导入恢复… → 取消导入(仅可用时) → 导出配置 → Treeview → 日志清空 → 日志 Text
```

- 搜索✕ 清空钮**不占 Tab 位**（视觉 v1.1 定稿：Esc 已等价清空）。

- 启动后初始焦点：搜索框（最高频操作是找软件）；若首扫完成且列表非空，Tab 一次即达列表。
- 置灰控件跳过不占 Tab 位。
- 每个可获得焦点的自绘控件必须有可见焦点环（样式跟随视觉规范/本文 D2）。

### 2.5 hover / cursor / 禁用态约定

| 场景 | cursor |
|---|---|
| 一切可点击且可用状态的按钮/搜索✕/分组行/右键目标 | hand2 |
| 输入框 | xterm |
| 置灰按钮/禁用区 | arrow（不可点击暗示） |
| 叶子行普通区域 | arrow（单击=选中，非点击暗示强的区域保持中性） |

按钮 hover 效果由视觉规范的 tk.Button 扁平化方案定义；本规范仅约束 cursor 一致性。

禁用态渲染按**视觉 v1.1 §9-③**：文字 #A8B0BB、底 #FAFBFC（Ghost 保持父底 #F4F6F8）、Secondary 描边降为 #EDEFF3、**禁用不区分按钮级别**（Primary 同样降灰，禁用浅蓝底=伪 affordance 禁止）；工程铁律：显式设 `disabledforeground="#A8B0BB"`，disable/enable 双向 config bg/highlightbackground，hover 函数首行判 disabled 直接 return。

### 2.6 线程与轮询（现状保留项的边界声明）

- `_poll` 120ms 轮询队列机制**保留不变**（功能语义）。
- 上述所有 UI 变更只发生在主线程队列消费点或事件回调内，禁止在工作线程直接触碰控件（现状正确，回归红线）。

## 3. 弹窗与反馈策略

### 3.1 保留弹窗的场景（白名单）

| 场景 | 形式 | 理由 |
|---|---|---|
| 导入前确认（「即将安装 n 个软件包…是否继续」） | 保留 messagebox.askyesno | 破坏性/耗时操作的事前确认必须显式 |
| 导入中关闭窗口确认 | 新增 askyesno（A8） | 同上 |
| 导入中断（exception） | 保留 showerror | 异常终态，低频 |
| 扫描失败 | **移除弹窗**（视觉规范已定页内文案），本规范确认并要求移除现 `_poll` 中的 `messagebox.showerror` | 高频可恢复错误不配模态 |
| 0 勾选点导出 | 理论不可达（按钮 disabled），保留 showwarning 作防御兜底 | 防呆 |

### 3.2 导出流程合并方案（A1，功能不变）

将「输入名称窗 + 成功结果窗 + 是否打开文件夹窗」三连合并为一个**自绘 Toplevel（transient 于主窗、grab_set 模态）**，两段式：

**第一段：导出设置**（面板规格见《视觉规范 v1.1》§9-②：宽 520px、1px #E1E5EA 边框、transient+grab_set、不可缩放、固定高内容容器两段原位切换、覆盖提示行固定高 20 占位）

```
┌ 导出配置 ─────────────────────── ✕ ┐
│  将导出已勾选的 N 个软件包（两份 JSON：      │
│  winget 原生格式 + 富 profile 格式）         │
│  配置名称                                   │
│  [ 我的软件配置________________ ]           │
│  ⚠ 同名配置将被覆盖            ← 仅重名时出现│
│  保存位置： D:\...\exports      ← 只读展示  │
│              [取消]  [导出]  ← Primary 实心 │
└─────────────────────────────────────┘
```

- 名称默认值「我的软件配置」保留；实时校验非法字符（A3）与重名（A2）。
- 主按钮 = 视觉规范唯一实心蓝规则在本对话框内的局部适用（对话框内它就是唯一 Primary）。
- Esc / ✕ / 取消 = 关闭且无任何副作用。
- 覆盖提示与非法字符错误的三态色严格按视觉 v1.1 §9-②：错误 边#B91C1C/底#FEF2F2/字#B91C1C；警告 边#FCD34D/底保持白/字 **#92400E**（amber-800，7.1:1；禁用 #B45309，不达 AA）。

**第二段：导出完成（同一 Toplevel 原位切换内容，不新开窗）**

```
│  ✓ 已导出 N 个软件包                        │
│    my-config.json / my-config.winget.json   │
│  ☑ 导出完成后打开文件夹          ← 默认勾选  │
│              [关闭]                          │
```

- 「打开文件夹」从问句改为**字符勾选 ☑/☐**（视觉 v1.1 定稿：与主列表视觉语言一致，不使用 tk.Checkbutton 原生方框）+ 关闭按钮：点关闭时若勾选则 `os.startfile`。默认勾选=保留现有「大多数用户想看文件」的默认行为，但用户不再被问句打断。
- 「关闭」按钮用 **Secondary 描边**（视觉 v1.1：完成段不做实心蓝，实心蓝只属于"下一步动作"）。✓ 图标 20pt bold #166534。
- 成功同时写日志（done tag + 文件路径，现有行为保留）。

### 3.3 页内反馈清单（替代弹窗）

| 场景 | 反馈位置与形式 |
|---|---|
| 扫描中/失败/空结果 | 列表空状态居中文案（C1 三态） |
| 搜索无结果 | 同上 + 状态栏「匹配 n / 共 m」（A6） |
| 复制包 ID | 状态栏左侧 2s 瞬时提示（2.1） |
| 取消导入已受理 | 状态栏「正在取消导入…」（A11） |
| 导入汇总 | 日志 done 行 + 状态栏（A9 前缀方案） |
| 勾选清理告知 | 日志 info 行（C3） |
| 导出成功/失败 | 导出对话框第二段 / 对话框内红字（不再走 showerror，异常文本就地展示） |

### 3.4 窗口关闭协议（WM_DELETE_WINDOW）

| 状态 | 行为 |
|---|---|
| SCANNING / SCAN_FAILED / READY | 直接销毁（勾选已 debounce 落盘，退出前强制 flush 一次） |
| IMPORTING / CANCELING | askyesno「导入尚未完成，确定取消并关闭吗？」→是：置 cancel_event 后 200ms 销毁（给工作线程观察点）；否：留在原界面 |

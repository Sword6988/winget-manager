# Winget 软件管家 · 视觉设计规范 v1.1

> v1.1 增补（第 9 章）：焦点环、导出对话框、禁用态、搜索框占位符与内嵌 ✕ —— 响应 UX 规范的 4 项样式空缺。
> **v1.1 相对 v1.0 的 4 处就地修订**：① 6.7 扫描中搜索框 disabled → 保持可用；② 6.4 数据行 tag 去掉 background、只留 foreground（避免覆盖选中态）；③ 9.1 顶部焦点条 `place` → `pack`；④ 5.3/6.3/9.4 搜索框 200 → 220px（工具栏预算 881 → 901）。复核明细见第 10 章。

> 目标平台：Windows 桌面端，Python 3.13 + tkinter/ttk（**零第三方依赖**），当前 ttk 主题 `vista`
> 视觉基调：干净、克制的现代 Windows 11（Fluent）浅色风格
> 本文档只定义**视觉规格**，交互流程与文案归属体验阶段。所有数值均可在纯 tkinter 内实现，标注 ⚠️/❌ 的项见第 7 章约束表。

## 1. 设计原则（5 条）

| # | 原则 | 具体含义（可验收） |
|---|------|------------------|
| P1 | **一个强调色，两个用途** | 强调蓝只用于「主操作按钮」和「计数/进度」两类元素；整个窗口的蓝色像素面积 ≤ 8%，实心蓝按钮同屏最多 1 个 |
| P2 | **层级靠表面明度 + 1px 描边，不靠阴影** | 三级表面：画布 `G2` → 面板/列表 `G0` → 凹陷区 `G1`。Tk 无阴影，禁止用「多层嵌套边框」制造层次 |
| P3 | **4px 基数节奏** | 所有间距取自 4/8/12/16/24；同一容器内 padding 只允许 2 种值（如工具栏 16 横向、10 纵向） |
| P4 | **3 个字号 + 2 个字重** | 全窗口只用 12pt/10pt/9pt 三档字号，只用 normal/bold 两种字重（Tk 限制）；层级不再由第四种字号承担 |
| P5 | **状态永远可见** | 任何 >300ms 的操作必须有进度反馈且禁用冲突按钮；任何批量操作结束必须有结果计数；空列表必须有引导文案 |

## 2. 现状问题清单（视觉维度）

> 「证据」列为 `gui_app.py` 现有实现，便于逐条对账。

### 2.1 阻断级（P0，直接影响可用性）

| # | 问题 | 证据 / 具体表现 | 影响 |
|---|------|----------------|------|
| V1 | **分组标题被裁切** | `tree.column("#0", width=64)` + `text=f"☐ {category} ({len(items)})"` → Treeview 单元格文字按列宽硬裁，实际只能看到「☐ 游…」 | 分组结构信息完全丢失，用户看不到分类名和数量 |
| V2 | **主按钮不存在视觉层级** | `style.configure("Accent.TButton", background=ACCENT)` —— vista 主题下 TButton 的 background 被原生绘制忽略，且该 style 从未被任何按钮使用 | 「导出配置 / 导入恢复」这条核心路径与「全选」视觉等价，用户找不到主操作 |
| V3 | **9 个按钮平铺、无分组、间距不一致** | 左侧灰度按钮 `padx=3`、右侧文件按钮 `padx=8`，全部同权重 | 认知负荷高，「反选」与「导入恢复」在视觉上同级，误点风险 |

| V6 | **`selectmode="none"` 让选中态样式成为死代码** | `style.map("Treeview", background=[("selected","#dbeafe")])` 永不触发；单击即切换勾选 | 无任何「当前行」反馈，鼠标跟丢；想复制包 ID 会误触勾选 |

## 4. 字体与字号阶梯

### 4.1 字体栈

- 正文族：`HarmonyOS Sans SC` → 回退 `Microsoft YaHei UI`（现有探测逻辑保留，属正确做法）
- 等宽族：`Consolas`（Windows 自带，必存）
- ❌ **Tk 不支持 CSS 式 font fallback 链**：`font=("HarmonyOS Sans SC", 10)` 遇到缺字时由系统字体链自动接管，开发者不可控。因此**不要依赖「字符字形」承载控件语义**（见 6.4 勾选列）。

### 4.2 阶梯（3 档字号 + 2 档字重）

| Token | 定义 | 100% DPI 像素 | 用途 |
|-------|------|--------------|------|
| `F-title` | `(FONT, 12, "bold")` | 16px | 顶栏应用标题 |
| `F-section` | `(FONT, 10, "bold")` | 13.3px | 区块标题（日志区头）、分组行、日志 `done` |
| `F-body` | `(FONT, 10)` | 13.3px | Treeview 行、按钮、输入框、日志正文 |
| `F-sub` | `(FONT, 9)` | 12px | 表头（bold）、状态栏、版本 chip、辅助说明 |
| `F-mono` | `("Consolas", 9)` | 12px | **仅用于** `tk.Text` 日志的时间戳列（Text 的 tag 支持混合字体 ✅） |

> **字号单位用「磅值」（正数）而非像素（负数）**：`SetProcessDpiAwareness(1)` 已开启系统级 DPI 感知，磅值会随 DPI 自动缩放；像素值不会，125% 下会缩水。所有**像素尺寸**（行高/列宽/间距）改用下面的 `px()` 换算。

### 4.3 行距与基线

- Treeview 行高：`s(28)`（100% 下 28px），文字垂直居中由 ttk 处理，不做额外偏移
- 日志 Text：`spacing1=s(2)`、`spacing3=s(3)`，行距约 1.45
- 按钮/输入框：单行，靠 `pady` 控高，不用 `<br>`

## 5. 间距与布局栅格

### 5.1 Spacing Token

| Token | 100% 值 | 用途 |
|-------|---------|------|
| `sp1` | 4px | 图标与文字间隙、字符内部微调 |
| `sp2` | 8px | 按钮之间、行内元素之间 |
| `sp3` | 12px | 区块之间（列表 ↔ 日志）、工具栏分组内 |
| `sp4` | 16px | 窗口左右 padding、工具栏分组之间 |
| `sp5` | 24px | 大区块分隔（本期不用，避免过松） |

```python
def px(self, n):  # 需在 App 实例内，winfo_fpixels 依赖 DPI
    return int(round(n * self.winfo_fpixels("1i") / 96))
```

### 5.2 窗口栅格（默认 1080×760，`minsize(960, 620)`）

```
┌─────────────────────────────────────────────────┐ padding x=16
│ 顶栏  56px   G0 底 / 标题 12pt bold / 版本 chip  │
├─────────────────────────────────────────────────┤ 1px G4
│ 工具栏 52px  G2 底 / 按钮 32px 高 / 上下 10px    │
├─────────────────────────────────────────────────┤ 12px 间距
│ Treeview（flex，min-height 240）                 │ ← 唯一 elastic 区
├─────────────────────────────────────────────────┤ 12px 间距
│ 日志区 148px（头部 32 + 1px + Text 115）         │ 固定高
├─────────────────────────────────────────────────┤ 1px G4
│ 状态栏 34px  G0 底                              │
└─────────────────────────────────────────────────┘
```

垂直预算（760 高）：`56+1+52+12+Tree+12+148+1+34 = 316 + Tree` → Tree 区 444px，表头 32 → 可显示 **14 行**（原实现 12 行）。

### 5.3 工具栏宽度预算（minsize 960 校验）

| 分组 | 内容 | 宽度 |
|------|------|------|
| 左 | 重新扫描（次按钮） | 88 |
| 左 | 搜索框 | **220**（v1.1 定稿，原 200） |
| — | 1px 分隔线 + 左右 16 间距 | 33 |
| 中 | 全选(48) 全不选(60) 反选(48) 仅选应用(78) + 3×8 间隙 | 258 |
| 右 | 取消导入(78) 导入恢复(88) 导出配置(88) + 2×8 间隙 | 270 |
| — | 窗口左右 padding | 32 |
| **合计** | | **901 / 960** ✅（留 59px 弹性给中间 spacer） |

> 若未来必须支持 820px：把「取消导入/导入恢复/导出配置」整体折到第二行右对齐（`<Configure>` 判宽切换），**不允许**压缩按钮宽度到出现文字截断。

### 5.4 三级表面与分隔规则

- 窗口底 = `G2`；顶栏/列表/日志/状态栏 = `G0`（日志 Text 内部 = `G1`）
- 区域之间只用 **1px `G4` 水平线**（`tk.Frame(height=1, bg=T["g4"])`），上下不加间距，间距由相邻容器 padding 提供
- ❌ 禁止 `tk.LabelFrame`、`relief="groove"/"ridge"`、`bd>1`

## 6. 组件视觉规范

### 6.1 顶栏（height 56，`G0`）

| 元素 | 规格 |
|------|------|
| 容器 | `tk.Frame(bg=G0)`, `pack(fill="x")`, 内部 `padx=16, pady=0`，用两个等高 spacer 实现垂直居中 |
| 应用标题 | `F-title`，`G10`，单行 |
| 版本 chip | `tk.Label(text="winget 1.9.25200 · DESKTOP-XX", bg=G2, fg=G7, font=F-sub, padx=8, pady=2)`，与标题间距 `12px`。**无圆角**（Label 不支持，不要为它引入 Canvas） |
| 分隔 | 顶栏底部 1px `G4` |
| 扫描中 | chip 文案换为 `正在扫描…`，`fg=G7`；不要闪烁、不要变色 |

### 6.2 工具栏（height 52，`G2`）

布局：`左组（重新扫描 + 搜索框） ｜ divider ｜ 中组（勾选类） ｜ spacer ｜ 右组（文件类）`，全部 `side="left"` + 一个 `pack(side="left", fill="x", expand=True)` 的空白牺牲帧撑开右组。

#### 按钮体系三级（**必须严格区分，这是本次改造的核心**）

| 级别 | 使用位置 | 底 | 文字 | 描边 | hover | press | 尺寸 |
|------|---------|-----|------|------|-------|-------|------|
| **Primary 实心** | 导出配置 | `#2563EB` | `#FFFFFF` | 无 | `#1D4ED8` | `#1E40AF` | 高 32，`padx=14` |
| **Secondary 描边** | 重新扫描、导入恢复 | `#FFFFFF` | `#4A525C` | 1px `#CFD5DC` | 底 `#F4F6F8` / 边 `#CFD5DC` | 底 `#EDEFF3` | 高 32，`padx=14` |
| **Ghost 幽灵** | 全选、全不选、反选、仅选应用 | `#F4F6F8`（=工具栏底，模拟透明） | `#4A525C` | 无 | `#EDEFF3` | `#E3E7EC` | 高 32，`padx=8`，字号 `F-sub` bold |
| **Danger Ghost** | 取消导入 | `#F4F6F8` | `#B91C1C` | 无 | 底 `#FEF2F2` | 底 `#FEE2E2` | 高 32，`padx=10` |
| **Danger Solid** | 取消导入（导入进行中） | `#DC2626` | `#FFFFFF` | 无 | `#B91C1C` | `#991B1B` | 高 32，`padx=12` |
| **Disabled（通用）** | 任意 | `#FAFBFC` | `#A8B0BB` | 1px `#E1E5EA` | 无变化 | 无变化 | — |

补充规则：
1. **同屏实心蓝按钮 ≤ 1 个**。当前主路径是「扫描 → 勾选 → 导出」，故只有 `导出配置` 实心；`导入恢复` 用描边蓝（`边 #BFDBFE` + 文字 `#1D4ED8`）作为「次主按钮」。若产品侧坚持两者同级，则两者都用描边，实心留给运行时唯一的动作按钮（导入进行中的「取消」）。
2. **删除 `▾` 字符**（V16）。若真要导出格式菜单，走下拉菜单后再加箭头，且箭头用 `▾` 之外的 `▾`… 统一要求：符号必须由需求驱动，不做装饰。
3. 按钮间距 `8px`，组间 `16px` + 1px `#E1E5EA` 竖线（高度 20，垂直居中）。
4. 焦点可见：键盘 Tab 到位时显示 1px `#93C5FD` 外环（`highlightthickness=1`）。

#### 实现选型建议（结论先行）

| 方案 | 圆角 | hover | 代码量 | 结论 |
|------|------|-------|--------|------|
| **A. `tk.Button` 扁平化** | 无 | 手工绑 `<Enter>/<Leave>` 改 `bg` | 低（每个按钮 6 行，可封装成 30 行工厂函数） | ✅ **工具栏全部按钮采用** |
| B. `tk.Canvas` 自绘 | 有（≤6px 干净） | 手工绑 | 中（需处理文字测量/重绘/焦点） | 仅当视觉验收强制要求圆角时，单独封装给 `导出配置` |
| C. `style.theme_use("clam")` 全局重配 | 无 | `style.map` 原生支持 | 中（须重配 TButton/TEntry/Treeview/Heading/TScrollbar 共 6 套） | 备选。**不建议首期**：Entry/Scrollbar 会变回 90 年代观感，需要额外 6 套 style 才追平 vista 的原生细腻度 |

方案 A 的关键实现约束（交给工程阶段）：
- `bd=0, relief="flat", highlightthickness=1, highlightbackground=<父容器底>, highlightcolor="#93C5FD", cursor="hand2"`
- vista 下 `tk.Button` 的 `activebackground` 只在按住时生效，**hover 必须手工绑定**；`<Leave>` 时若鼠标已移出窗口需兜底复位
- `state="disabled"` 时 Windows 会用 `disabledforeground` 覆盖文字色、底变系统灰 → **必须显式设置 `disabledforeground=#A8B0BB`，且禁用时同步 `config(bg="#FAFBFC")`**
- Ghost 按钮的「透明感」靠 `bg` 与父容器完全同色实现；换父容器底色必须同步改按钮 `bg`（Tk 无 alpha）

### 6.4 Treeview（核心列表）

| 属性 | 规格 |
|------|------|
| 行高 | `rowheight = s(28)`；`font=F-body`；`background=G0`, `fieldbackground=G0`, `borderwidth=0` |
| 去外框 | `style.layout("Treeview", [("Treeview.treearea", {"sticky":"nswe"})])` |
| 表头 | 高 `s(32)`；`background=G3`, `foreground=G8`, `font=(FONT,9,"bold")`, `padding=(s(10), s(8))`, `relief="flat"`, `borderwidth=0`；`map(background=[("active", G4)])`。⚠️ vista 下表头底色在部分 Tk 版本不生效，若不生效则**只调字重/字距，接受原生渐变表头**，不要改用 clam 只为表头 |
| 列宽 | `#0` 勾选 56（center, stretch=False）／`name` min 220, stretch=True／`id` 260（anchor w）／`ver` 110（anchor **e**）／`cat` 110（anchor w） |
| 列内边距 | ttk 不支持单元格 padding → 用 `anchor` + 列宽 + 表头 `padding` 模拟，首列左侧留白由 `#0` 宽度承担 |
| 滚动条 | `ttk.Scrollbar` 保持 vista 原生，宽度不干预 |
| 交互光标 | 默认箭头；`<Motion>` 命中行内时 `tree.config(cursor="hand2")`，离开复位 → 这是 Tk 下唯一可行的「可点击」反馈 |

#### 行状态（用行级 tag，因为 ttk 只支持行级样式）

| Tag | 适用 | `foreground` | `background` | `font` |
|-----|------|-------------|-------------|--------|
| `on` | 已勾选的数据行 | `#2A3038` (G9) | **不设**（保持 fieldbackground `G0`） | `F-body` |
| `off` | 未勾选的数据行 | `#4A525C` (G8) | **不设**（保持 fieldbackground `G0`） | `F-body` |
| `group` | 分类分组行 | `#2A3038` (G9) | `#F4F6F8` (G2) | `F-section`（bold） |

- **勾选态用「文字墨度」表达，不用颜色**：勾选 = 一级墨 `G9`，未勾选 = 二级墨 `G8`。两者都 ≥7.8:1，可读性无损，且长列表里能一眼看出「哪些是我选的」。
- **数据行 tag 只设 `foreground`，不设 `background`**（v1.1 修订，原表误设 `G0`）。理由：UX D2 的键盘可达性要求启用选中态（`selectmode="browse"`），而 item tag 的 `background` 在部分 Tk 版本会盖掉 `style.map(..., [("selected", …)])`，症状是「选中了但看起来没选中」，且极难定位。数据行底色本就等于 fieldbackground `G0`，tag 再设一遍属冗余，去掉即零成本消除该冲突。
- **选中态映射**：`style.map("Treeview", background=[("selected","#DBEAFE")], foreground=[("selected","#2A3038")])`。即使个别 Tk 版本让 tag 的 `foreground`（G8）覆盖选中态文字色，`G8 on #DBEAFE` 仍有 **6.4:1**，可读 —— 因此**不需要**在 `<<TreeviewSelect>>` 里重打 tag。这是刻意的鲁棒性设计：不为版本差异写补偿逻辑。
- **分组行始终设 `bg=G2`**（它需要色块），但**分组行必须不可被选中**：点击分组 iid 走「整组切换」分支，并在处理后 `selection_remove(iid)`；否则会出现「整行 #DBEAFE 的蓝色块头」压住 G2 底色，分组层级感消失。
- **本期不做斑马纹**。理由：① 需要 `on/off × even/odd` 四个组合 tag，与选中态的 tag/map 覆盖关系叠加后不可控；② 行高 28 + 分组块状底色已提供足够的行间分隔；③ 收益低于维护成本。若后续坚持要，务必用 4 个组合 tag（不要靠 tag 叠加优先级），且数据行仍不设 bg、只在奇偶行用极低对比 `#FAFBFC`。

#### 分组行（重构现有实现，修 V1）

| 项 | 规格 |
|----|------|
| `#0` 列（宽度 56） | 三态标记：`☑` 全部勾选 / `▣` 部分勾选 / `☐` 全未选；`anchor="center"`，**不再放分类名** |
| `name` 列 | `f"{category}"`，`F-section` bold，`G9` |
| 其余列 | 空字符串 |
| 视觉 | 全行底 `G2`，与白色数据行形成块状分隔；展开箭头保留 Treeview 自带 indicator（默认已展开） |
| 计数 | 放在 `cat` 列：`f"{sel}/{n}"`，`F-sub`，`G7` —— 既不挤压名称，又能横排对齐（**注意**：`cat` 列此时语义变为「计数」，或新增一列 `pick`，由体验/工程阶段定，视觉上要求「计数右对齐、弱化」） |

> 备选（更彻底）：分组行 `#0` 留空，分类名走 `name` 列并整体加 `▣` 前缀；但三态标记就失去了对齐参照物，不推荐。

#### 勾选列的两种方案

| 方案 | 做法 | 优点 | 缺点 | 建议 |
|------|------|------|------|------|
| **① 字符方案（本期采用）** | `#0` 列宽 56 居中显示 `☐/☑/▣` | 零成本、可点击区域明确（整行可点）、三态清晰 | 字形由系统回退字体决定，大小/基线不完全受控；无法给勾选符单独上色（tag 是行级的） | ✅ 保留。规范要求：`#0` 列宽 56 且 `anchor="center"`，让字形不管多大都居中，视觉上像「控件」而非「文字」 |
| ② PhotoImage 方案（升级路径） | 纯 tkinter 生成 16×16 `PhotoImage`（`put` 逐像素或程序化画 1px 边框 + 对勾），挂在 `#0` 列 item `image` 上 | 像素级一致、可用 `#2563EB` 给勾选符独立上色 | 必须改结构：`#0` 列同时承载 image 与树缩进，子行会被缩进 20px 而父行不会，垂直不对齐；需把层级压平或接受错位 | 仅在「字符方案被验收否决」时启用 |

> 相关约束：`#0` 列的 image 是 Treeview **唯一**支持图片的位置，普通列只能显示文本。这是上述取舍的根因。

### 6.8 空状态 / 错误态

- **空列表**：Treeview 内无法绘制占位文字 → 在 tree 容器内 `place(relx=0.5, rely=0.45, anchor="center")` 一个 `tk.Label(bg=G0, fg=G7, font=F-body, justify="center")`，文案 `尚未扫描到软件\n点击上方「重新扫描」开始`；扫描开始时 `place_forget()`
- **扫描失败**：不使用 `messagebox` 独占弹窗（打断感强），改为日志 `error` 行 + 状态栏左文本 `#B91C1C` + 空态 Label 换成 `扫描失败 · 查看下方日志`。弹窗仅保留给「需要用户决策」的场景（删除、覆盖、继续导入）
- **无勾选点导出**：保持现有 warning 弹窗，但视觉上应先让 `导出配置` 在 0 勾选时呈现 disabled（`Fg #A8B0BB`），从源头避免无效点击

## 9. v1.1 增补（响应 UX 规范 4 项空缺）

### 9.0 通则：双层描边（一次性解决所有「谁覆盖谁」的取舍）

规范中所有「描边」拆成两个**互不抢像素**的层：

| 层 | 厚度 | 承载 | 位置 |
|----|------|------|------|
| 外层（语义/常驻） | 1px | 默认 `#CFD5DC`、错误 `#B91C1C`、警告 `#FCD34D`、成功 `#86EFAC` | 由**父级 Frame 的 bg** 绘制 |
| 内层（焦点环） | 2px | `#2563EB` | 由控件自身 `highlightthickness` 绘制（Tk 天然画在内沿） |

结构（所有带描边的可交互控件统一）：

```python
outer = tk.Frame(parent, bg=T["g5"])        # 外层 1px 描边 = 这个 Frame 露出的 1px
w = tk.Entry(outer, bd=0, relief="flat",
             highlightthickness=2,
             highlightbackground=T["g0"],    # 静息：与自身底同色 → 隐形
             highlightcolor=T["b600"])       # 聚焦：2px 蓝环
w.pack(padx=1, pady=1)                       # 1px 即外描边
```

状态优先级（低 → 高）：`disabled < default < hover < press < error`，**焦点环不属于这条链路，它并行叠加**。因此「错误红边 + 聚焦蓝环」可以同时存在，无需二选一。

### 9.1 焦点环

| 属性 | 定稿 |
|------|------|
| 厚度 | 2px（不变） |
| 颜色 | `#2563EB`（白底 5.1:1，压 `G1/G2` 底仍 ≥4.8:1） |
| 位置 | 控件内沿，不外扩 → 不影响布局 |
| 位移 | **零**。铁律：`highlightthickness` 在静息/聚焦之间**恒定不变，只切颜色**。若在两个状态间改 thickness，控件会跳 2px（肉眼可见） |

按控件类型的落法：

| 控件 | 焦点环实现 |
|------|-----------|
| Primary / Ghost 按钮（无描边） | `highlightthickness=2`；静息 `highlightbackground` = 自身底色（隐形），聚焦 `highlightcolor=#2563EB` |
| Secondary 按钮（1px 描边） | 走 9.0 双层：外层 Frame `#CFD5DC`。聚焦时**同时**把外层 Frame.bg → `#93C5FD`、内层 `highlightcolor` → `#2563EB`，形成「外 1px 浅蓝 halo + 内 2px 深蓝环」（Fluent 观感） |
| 输入框（`tk.Entry`） | 同 Secondary 双层；错误态外层换 `#B91C1C`，焦点环仍在内层 → 红边与蓝环共存 |
| Treeview | **不加四周环**（会与滚动条/表头错位）。改用「顶部焦点条」：在列表容器内、tree **之前**放一条 2px `tk.Frame`，用 `pack(fill="x")` 正常占位（❌ **不要用 `place`** —— `place` 会浮在表头之上、遮住表头点击与列宽拖拽，症状是"表头点不动"）；获焦 `bg=#2563EB`、失焦 `bg=#E1E5EA`。焦点条占 2px 真实空间，行数预算从 444 → 442，仍为 14 行，不影响布局 |
| 日志 Text | 同上，改 `highlightthickness=2` 内环即可（Text 本身支持，且不影响行高） |

**焦点行 vs 选中底色的叠放（UX 的 D2 疑问）**

两者是**不同维度**的信号，因此不存在「叠放取舍」：

- 行级信号 = 选中底 `#DBEAFE`（文字 `#2A3038` 对比 **10.9:1** ✅；压 `G8` 时 6.4:1 ✅）
- 控件级信号 = 焦点环 / 顶部焦点条，位于**控件边界**，不进入行内

规则：

1. 列表**未**获焦：焦点条 `#E1E5EA`，选中行仍保持 `#DBEAFE`（保留上次位置，便于切回窗口后定位）
2. 列表**已**获焦：焦点条 `#2563EB`，选中行不变
3. ❌ 禁止给选中行再加蓝边/蓝左边框：Tk 做不到，且 `#2563EB` 与 `#DBEAFE` 相邻会形成脏色阶
4. 鼠标点击也显示焦点条（Tk 无法区分 focus 来源）—— 接受此代价，不做 hack
5. 唯一例外：行内「已勾选」用墨度（`G9`）表达，与选中底 `#DBEAFE` 叠加后对比 10.9:1，无冲突

### 9.3 禁用态渲染

| 级别 | 文字 | 底 | 描边 | 光标 |
|------|------|-----|------|------|
| Primary disabled | `#A8B0BB` | `#FAFBFC` | — | `arrow` |

| Ghost disabled | `#A8B0BB` | `#F4F6F8`（保持父底色） | — | `arrow` |
| Danger disabled | `#A8B0BB` | `#FAFBFC` | — | `arrow` |

规则：

1. **禁用态不区分级别**：Primary 也降为 `#FAFBFC` 底 + `#A8B0BB` 文字。刻意为之 —— 禁用即退出层级体系，绝不做「浅蓝 #93C5FD 底」这种伪 affordance（看起来还能点）

4. 对比度：`#A8B0BB` 2.2:1 —— WCAG 显式豁免 disabled 控件，允许；但**这是下限**，禁止更浅
5. 实现铁律（`tk.Button` 扁平化）：Windows 会强制用 `disabledforeground` 覆盖 `fg`、底刷成系统灰 → 必须显式 `disabledforeground="#A8B0BB"`，并在 disable/enable 时手动双向 `config(bg=..., highlightbackground=...)`；hover 处理函数第一行判 `str(w.state()) == "disabled"` 直接 return
6. 输入框：`tk.Entry` 支持 `disabledbackground="#FAFBFC"` + `disabledforeground="#A8B0BB"`，可做干净
7. **已采纳并生效（原为对 UX 的反馈，UX_SPEC §2.2 已同步）**：扫描期间**不禁用搜索框**（纯本地过滤旧数据，禁用反而打断用户），只禁用 4 个勾选按钮。此条同时修订了 6.7 节 v1.0 的「搜索框 disabled」表述

### 10.1 第 2 条连带新增的 3 条必读条款

1. **数据行 tag 只设 `foreground`，不设 `background`**（原 §6.4 表误设 `G0`）。item tag 的 bg 在部分 Tk 版本会盖掉 `style.map(..., [("selected", …)])`，症状是「选中了但看起来没选中」——属最难排查的一类 bug，且代码审查看不出来。数据行底色本就等于 fieldbackground `G0`，冗余设置去掉即零成本消除冲突。
2. **分组行仍设 `bg=G2`，但必须不可被选中**：点击分组 iid 走「整组切换」分支，处理后 `selection_remove(iid)`。否则会出现「整行 `#DBEAFE` 的蓝块头」压住 `G2` 分组色块，分组层级感直接消失。
3. **附带收益（少一段易错代码）**：因 `G8 on #DBEAFE` 仍有 **6.4:1**，即使个别版本让 tag 的 fg 覆盖选中态文字色也依旧可读 → **不需要**在 `<<TreeviewSelect>>` 里重打 tag。这是刻意的鲁棒性设计，不为版本差异写状态同步逻辑。
